Layer 5 · Owner-directed change

A Request Needs an Owner

The rpg-api dungeon prototype was deliberately where the pieces met. Its first lesson was a boundary: rules should describe the change they need; state owners should know how to apply it. Actions became things a Character could hold, and Flurry of Blows tested both ideas at once.

01The answer to Layer 4
Inside the deliberate prototype

The rule asks. The owner changes itself.

Layer 4 ended with a condition reading a live object and changing it directly. That condition had to know both the result it wanted and how Character applied that result without breaking its own invariants. A typed request became the boundary contract: the rule described the desired change; Character's listener owned the mutation.

The ownership rule: The rule asks. The owner changes itself.
022026-01-02 → 01-07
A new thing a Character can hold

Actions become part of the character

The new Action type represented something a Character could do. Basic combat supplied lasting options. Features could grant temporary ones. When doing an Action required a wider interaction, the Action published a uniquely typed request.

The new seam: A Feature can grant something to do without becoming the Action that does it.
03Flurry → 2026-01-26
The hardest real case becomes visible

One feature grants two strikes

Flurry of Blows spent one Ki, created two temporary Flurry Strikes, and asked Character to add both. The prototype then exposed the current Flurry capacity as an available combat control.

The breakthrough: Feature asks. Character owns the mutation. The player sees the result.
042026-02-08 · the horizon
The successful prototype reveals the next seam

The request still needs a driver

Selecting Flurry Strike needed a complete interaction, not one local mutation. The rpg-api dungeon prototype made it real through a dedicated path. Every successful new request taught that prototype another sequence of loading, wiring, resolving, persisting, and translating.

The request had an owner. The interaction still needed a driver.
