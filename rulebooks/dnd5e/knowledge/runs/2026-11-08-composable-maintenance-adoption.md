## Decided

- ResumeApplication reconstructs candidate creation only against the existing exact live owner and unchanged intended bindings/maintenance. It cannot create an owner or refill membership; the frozen cast retains its declaration/execution position, not another lifetime — [R11](https://github.com/KirkDiggler/rpg-toolkit/pull/2323#issuecomment-6755782119).
- Applied facts carry ApplicationID for adopted payloads without backlinks. A delivery at an intended adopted slot cannot omit its generation; matching a ref/address alone is not proof that this invocation delivered it — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).
- Authored information keeps all duration parts separately; the single-clock convenience view exists only for exactly one clock. Concentration can have no duration, and duration need not imply concentration — [approved plan](https://github.com/KirkDiggler/rpg-toolkit/pull/2323).
- Concentration end facts carry MaintainerID/SourceRef/SourceName, not item identities labelled as spells. The native spell-only projection must enforce its explicit supported-source boundary during T9; no new wire contract is implied — [approved plan](https://github.com/KirkDiggler/rpg-toolkit/pull/2323).
- Preserve gameplay assertions through current parts and real binding/keepers rather than keep a test-only imitation of the retired runtime. Damage/DC, every end reason, source-isolated cleanup, grace/reload and round-independent turn-end counting remain tested; old exact-wire and fallback-constructor checks become strict obsolete-format refusal — [fresh-character authority](https://github.com/KirkDiggler/rpg-toolkit/pull/2323#issuecomment-6726787390).
- Recipient rest must end one attachment, not its whole application. A neutral EndAttachment terminal scope expresses that existing distinction; named Bless/Bane compose the ordinary end-on-rest part with their dice payload instead of recovering a handwritten rest subscriber — [scope contract](https://github.com/KirkDiggler/rpg-toolkit/blob/design/bless-bane-composition/docs/ideas/composable-maintenance/README.md#separations-that-look-like-one-thing).
- Linked removals carry ApplicationID in addition to replacement address. The binding rejects stale/foreign facts before mutation, and both keeper implementations use one shared matcher so an old fact cannot strip a new invocation at the same address — [R4/R7](https://github.com/KirkDiggler/rpg-toolkit/blob/design/bless-bane-composition/docs/ideas/composable-maintenance/design.md#law).
- Pure Prepare validates linked part declarations without inventing a recipient. CreateRecipient validates adopted configs against an actual candidate and therefore belongs in native preflight before payment; Seal only accepts actually applied receipts and CheckComplete refuses provisional/orphaned state — [construction contract](https://github.com/KirkDiggler/rpg-toolkit/blob/design/bless-bane-composition/docs/ideas/composable-maintenance/README.md#construction-delivery-and-persistence).
- Keep one roll selector but expose an ordered contributor set per condition; each part retains its group, and metadata errors propagate. Plural information rows carry the same provider-owned group, so a mixed composition cannot flatten Bless/Bane or show a shadowed die as applying — [R5](https://github.com/KirkDiggler/rpg-toolkit/blob/design/bless-bane-composition/docs/ideas/composable-maintenance/design.md#law).
- Local payload attachment is not application admission: full graph validation belongs to the interaction binding, and an unbound application-ending part refuses transport rather than silently deleting a coordinator. This permits honest recipient-only projection without inventing a remote owner — [linked contract](https://github.com/KirkDiggler/rpg-toolkit/blob/design/bless-bane-composition/docs/ideas/composable-maintenance/README.md#construction-delivery-and-persistence).
- A reactive concentration output checks the provider's CanReact permission before requesting a save, separately from contributions still available during end reporting; this consumes provider eb5ffb63 rather than copying lifecycle state — [provider #2327](https://github.com/KirkDiggler/rpg-toolkit/pull/2327).
- RollQuery names the actual roll recipient, while a save-shaped outgoing action does not make its caster a saver; signed dice, selection group and source come from the same kind assessment used by information — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).
- Existing damage bonuses explicitly require scalar results; information uses nil for absent amounts. This is current numeric semantics, not a compatibility evaluator or a hidden die roll — [amount contract](https://github.com/KirkDiggler/rpg-toolkit/blob/design/bless-bane-composition/docs/ideas/composable-maintenance/README.md#describing-amounts-and-query-only-outputs).

## Found

- Real keepers now save/reload an owner with one delivered and one pending recipient, preserve the earlier d4, resume by the same application and finalize the remaining entry. No-effect outcomes keep zero-delivery semantics; unfinalized actual delivery, changed intent, duplicate/ended finalization and late resurrection are refused — [R11](https://github.com/KirkDiggler/rpg-toolkit/pull/2323#issuecomment-6755782119).
- Adopted missing-generation and repeated foreign-generation facts reproduced behavioral RED before correction. Dirty-notification and changed-intent mutants fail the resumed persistence tests; exact restoration passes the owning tests — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).
- Native adoption exposes an open lifecycle boundary: Bane can persist earlier delivery while a later target waits for an answer, but the root binding requires sealed membership. R11 returns only this decision; neither bypassing validation nor delaying delivered effects is authorized — [R11](https://github.com/KirkDiggler/rpg-toolkit/pull/2323#issuecomment-6752508135).
- The transport still wrote arbitrary origin refs into SpellRef. The new generic-source end-report test first failed against the missing neutral fields; it now passes with real non-spell creation, reload, concentration loss and recipient cleanup — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).
- Strict current cast decoding refuses an obsolete combined concentration field instead of silently dropping upkeep. Clone tests mutate declaration bytes, and frozen round trips preserve the authored grace and maximum — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).
- Historical concentration loading first succeeds where the new refusal test expects an error, then fails after retirement. Current ConcentrationHeld checks detect multiple claims; Character.Concentration propagates errors instead of converting invalid state to absence — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).
- Retired ConcentratingConditionSuite gameplay maps to ApplicationBindingSuite's damage/DC, seven end paths, actual clock/reload and unrelated-removal tests; keeper pruning/two sources/rest/self-ending/held-view/nested removal remain in ConcentrationKeeperSuite, and blob/address validation remains in LinkedDataSuite — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).
- Named current creation and obsolete-data refusal tests fail against the old registry path, then pass after retirement. Existing rest regressions caught missing recipient-local lifetime behavior; EndAttachment restores them, and a real-keeper multi-recipient rest test leaves the other recipient/hold alive until actual last-child loss — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).
- Fixture migration preserves dice, source, rest, reload and selection assertions while replacing old struct/constructor assumptions. Opaque output IDs are tested for stable uniqueness and source identity rather than parsing the retired single-row encoding — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).
- The first real replacement test accepted a stale old removal and deleted the new recipient; application-tagged binding/keeper checks turn that observed RED green. Mutants removing those checks fail both the real bound replacement and standalone-keeper regressions — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).
- Real keeper tests cover internal and externally initiated end order, last-member/duplicate notices, missing/foreign/competing ownership, pure preparation, actual-receipt sealing, zero delivery, self-recipient loss and independent payload survival; full root gates pass without treating these as browser or native-cast acceptance — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).
- The old registry Origin guard inferred support from the Raging-only composition field; explicit descriptor capability now admits linked creation without a ref-name switch. Existing registry coverage fixtures expose the new ref and retain their behavior checks — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).
- A plural-row selection mutant makes the second Bless source falsely apply and retain a benefit; the mixed-group execution/information assertion fails before exact restoration — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).
- Adopting the pushed provider first exposes four compile failures in the integer-only root evaluator/vocabulary; explicit scalar producers/consumers restore the existing conditions/effects tests without changing Raging gameplay — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).

- New part APIs first fail by absence; resistance binding, nil-request attribution and payload inspection fail behaviorally before correction. Mutants dropping reaction permission, exact-owner qualification and subtraction fail the corresponding tests before exact restoration — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).

The first roll implementation also confused the single Answer.Roll with plural Effect rows; roll data now stays in the shared kind assessment without changing the information-row contract — [S14](https://github.com/KirkDiggler/rpg-project/issues/904).
