01The return
Every option on the table

What would I build if I started over?

The break had left every option open. I still liked what the tools could do, but the toolkit had become hard to rethink from inside its existing shape. Starting again in C++ let me ask a different question: not how to repair this implementation, but how I would build it now.

02A fresh setting
A different game, familiar questions

Smaller goals. Familiar pressure.

I used the card game Across the Obelisk as a use case because of its conditions and resistances, not because its rules were simple. I already knew the toolkit’s conditions needed help. A small card-game experiment gave me a place to explore those interactions with a fresh approach.

A smaller first slice did not remove the hard interactions.
03Inside Unreal
From making it to building with it

I was making a tool again

I don’t remember which class it was. I remember seeing a class I’d written in C++ show up in Unreal’s Blueprints. I was learning more about the language and the engine, but that was the part that stayed with me: I could build with something I had made.

04Realignment
Remembering the purpose

Bring that purpose back

The toolkit was becoming an application. The C++ work reminded me that I am a tool builder. I love building things with great tools. That was more than a reason to enjoy the experiment. It was a reason to reconsider what the toolkit itself should be.

The game still mattered. So did the tools. I wanted useful pieces I could put together, not a toolkit that decided the whole application’s shape. That meant looking again at Encounter, the toolkit module that ran the game. Working was not the only test.

The toolkit was supposed to make the game easier to build.
Not become the application I had to build around.
