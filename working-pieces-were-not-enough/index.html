Fixing those descriptions helped. It also made the larger job clearer: I needed to reconsider how the pieces fit together.

01March 2026
Follow the action’s result

An action happened. The accounts disagreed.

Granting a Strike and using it were separate steps. That made the action model clearer. But once the strike happened, its result still had to travel through the game. A combat update could reflect the damage while the same monster’s hover panel still called it uninjured.

Resolving a change did not make every description current.
02Inside the client
The stitching was everywhere

Each view held part of the creature

The map drew placements from one container. Monster health came from another. Character appearance lived elsewhere again. Combat events had to reconcile those slices, and their updates could drift. A local fix corrected one path; it did not establish how every account stayed in step. The repeated stitching was a problem with the connections, not just the displays.

The views were being synchronized by convention.
03March → April 2026
Change the contract, not each display

A shared record fixed one boundary

The new EntityState contract gathered identity, position, health, conditions, and rendering details into one entry. A snapshot could replace the encounter view; smaller updates replaced affected entries by ID. The map and hover panel could read the same received creature. That answered a client-state problem. It did not yet answer how the whole fight held together.

One consistent view was not yet one coherent system.
04The larger undertaking
The gaps were between the pieces

The next change was architectural

The fixes were useful, but they were still fixes to pieces. The API had an orchestrator; that did not mean the pieces formed a coherent system. A shared client record made some views agree. It did not settle which state the next interaction should load or how changes should survive the whole trip.

05The pause
Away from the code

The tools needed a way to work together

An architecture-level update was more than I could give the project then. Work needed attention, and my training for a 108 km ultra was reaching 80 to 100 km a week. The break became obvious.

Running gave me time to think without getting caught in implementation. I had to hold the problem in my head. I liked what the tools could do. I still needed a way for them to work together. It felt like I had been making a prototype all along.

Working pieces were not enough.
When I came back, every option would have to be on the table.
